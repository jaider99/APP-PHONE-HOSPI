# Review Center Pipeline Analysis

## 1. Current Review Center screen widget tree

- `ReviewCenterScreen` is a `ConsumerStatefulWidget` in `lib/features/review_center/presentation/screens/review_center_screen.dart`.
- `initState` invalidates `syncReviewItemsProvider` and starts `ref.read(syncReviewItemsProvider.future)` with `unawaited`, so the screen tries to synchronize server-side review rows when opened.
- `build` watches:
  - `reviewItemsProvider` for the open inbox list.
  - `reviewItemCountsProvider` for header counts.
  - `syncReviewItemsProvider` for sync state.
  - `selectedReviewFilterProvider` for the active filter.
- Main layout:
  - `Scaffold`
  - `RefreshIndicator`
  - `CustomScrollView`
  - `SliverToBoxAdapter` header/count/filter area
  - `SliverList` of review item cards when rows exist
  - `_ReviewEmptyState` when `reviewItemsProvider` returns an empty list
  - `_ReviewErrorState` when `reviewItemsProvider` fails

## 2. Current route

- Review Center is routed through `AppRoutes.reviewCenter` at `/review-center`.
- The route opens `ReviewCenterScreen` directly.

## 3. Providers

- `selectedReviewFilterProvider`: stores the current Review Center filter.
- `reviewCenterRepositoryProvider`: constructs `ReviewCenterRepository` with the Supabase client.
- `reviewCenterRealtimeProvider`: subscribes to `review_items` changes scoped by `company_id`.
- `reviewItemsProvider`: fetches open review items for the active company and filter.
- `reviewItemCountsProvider`: fetches counts for the active company.
- `syncReviewItemsProvider`: calls `sync_review_items_for_company`, then invalidates items/counts.

## 4. Repository

`lib/features/review_center/data/repositories/review_center_repository.dart` is the Review Center data access layer.

- `fetchOpenItems` reads from `review_items` with:
  - `company_id = active company`
  - `status = open`
  - optional filter converted to a list of `review_type` values
  - sorted by severity and `created_at`
- `fetchCounts` reads open `review_items` for the company and calculates:
  - open count
  - critical count
  - AI review count
  - price alert count
- `syncCompanyReviewItems` calls RPC `sync_review_items_for_company` with `p_company_id`.
- `resolveItem`, `ignoreItem`, `retryItem`, and `resolvePriceAnomaly` mutate review status or trigger the related action.

## 5. Supabase tables used

Current Review Center code directly uses:

- `review_items`: primary inbox table read by the screen.
- `documents`: source table for failed extraction, duplicate document, missing category, unknown supplier, unknown document type, and document-needs-review items in the sync RPC.
- `document_items`: source table for product matching review items in the sync RPC.
- `price_anomalies`: source table for price anomaly review items in the sync RPC and price anomaly resolution.

Existing operational source tables that should also feed Review Center:

- `sales_imports`: failed/flagged/low-confidence sales import issues.
- `pos_connections`: broken POS connection/sync/credential states.
- `pos_connection_requests`: pending/requested POS setup requests that need operator follow-up.
- `product_prices`: price baseline/variation context, usually surfaced through `price_anomalies` or a baseline review rule.
- `products`: product matching/baseline context.

## 6. Whether `review_items` exists

Yes. Live database inspection confirms `public.review_items` exists.

Important live properties:

- RLS is enabled.
- Policies scope `SELECT`, `INSERT`, and `UPDATE` to `company_id = ANY(public.user_company_ids())`.
- Realtime publication includes `review_items`.
- Unique source constraint exists on `(company_id, review_type, source_table, source_id)`.
- Live `review_items` row count is currently `0`.

Security note: project context previously flags that `review_items` does not force RLS. The current policies are tenant-scoped, but a hardening migration can add `FORCE ROW LEVEL SECURITY` without weakening access.

## 7. Whether Review Center reads only `review_items`

Yes for the visible inbox and counts.

The screen does not directly query `documents`, `document_items`, `price_anomalies`, `sales_imports`, or POS tables. It reads generated rows from `review_items`. Those source tables only affect Review Center if `sync_review_items_for_company` successfully materializes source signals into `review_items`.

## 8. Whether `review_items` are generated

They are intended to be generated by `public.sync_review_items_for_company(uuid)` and related document sync functions.

Live behavior today:

- `review_items` is empty.
- Opening the screen triggers the sync provider, but the RPC fails.
- Executing `sync_review_items_for_company` as the active company owner in a rollback transaction fails with:

```text
ERROR: 42703: column d.supplier_name does not exist
CONTEXT: PL/pgSQL function sync_review_items_for_company(uuid) line 114 at SQL statement
```

The failing statement is in the duplicate-document insert metadata and references `d.supplier_name`. The live `documents` table does not have `supplier_name`; supplier identity is represented through `provider_id`, extracted JSON fields, or supplier/provider tables depending on the flow.

Result: no rows are generated, even when valid source signals exist.

## 9. Current filters: status, review_type, severity, company_id

- `company_id`: always supplied by the active company provider and used in repository queries and realtime filter.
- `status`: repository fetches visible items with `status = open` only.
- `review_type`: active filter maps to one or more review types.
- `severity`: not exposed as a direct filter; used for sorting and critical counts.

Current DB allowed `review_type` values:

- `low_confidence_field`
- `duplicate_document`
- `missing_category`
- `failed_extraction`
- `product_match_review`
- `supplier_match_review`
- `price_anomaly`
- `document_needs_review`
- `unknown_supplier`
- `unknown_document_type`

Missing for the requested operational inbox scope:

- `price_variation`
- `baseline_review`
- `failed_sales_import`
- `low_confidence_sales_report`
- `missing_sales_period`
- `pos_connection_issue`

## 10. Count logic: Open, Critical, AI review, Prices

Current count logic is computed from open `review_items` rows.

- Open: every row with `status = open`.
- Critical: every open row with `severity = critical`.
- AI review: currently limited to `failedExtraction`, `lowConfidenceField`, and `unknownDocumentType`.
- Prices: currently limited to `priceAnomaly`.

Gaps:

- Product/supplier matching issues are operational AI review issues but are not counted in AI review.
- Document-needs-review is not counted in AI review.
- Sales extraction/import issues are not represented in the model or counts.
- POS connection/setup issues are not represented in the model or counts.
- Price variation/baseline review types are not represented in the model or counts.
- The screen uses `counts.valueOrNull ?? ReviewItemCounts.empty()`, so counts can display as zero while counts are loading or if the counts provider failed.

## 11. Realtime subscriptions

`reviewCenterRealtimeProvider` subscribes to Supabase Realtime on `review_items`, filtered by the active `company_id`.

On `INSERT`, `UPDATE`, or `DELETE`, it invalidates:

- `reviewItemsProvider`
- `reviewItemCountsProvider`

Live database check confirms `review_items` is in the `supabase_realtime` publication.

## 14. Why screen shows “All clear”

The screen shows “All clear” because `reviewItemsProvider` returns an empty list from `review_items`.

The table is empty because generation fails inside `sync_review_items_for_company` before it can insert rows. Since the initial sync is unawaited in `initState`, a sync failure can be missed by the visible list provider. The list provider then performs a valid query against an empty table and renders the empty state.

This is not a visual-only empty state bug. The visible symptom is downstream of a broken data generation pipeline.

## 15. Root cause

Primary root cause:

`public.sync_review_items_for_company(uuid)` has schema drift. It references `documents.supplier_name`, but the live `documents` table does not contain that column. The function crashes with SQL error `42703`, so no review rows are generated.

Secondary causes/gaps:

- The DB constraint and Dart model only know the original 10 review types.
- Sales and POS operational issues are not generated into `review_items`.
- Price anomaly source rows exist, but they are not visible because the RPC crashes before reaching reliable generation.
- Count groupings do not cover all operational review types requested for the inbox.
- The UI can show zero counts while counts are loading or failed.
- Initial sync errors are not surfaced strongly enough to prevent a misleading “All clear” state.

## 16. Minimal safe fix

Server-side fix first:

1. Add a targeted Supabase migration that replaces `sync_review_items_for_company` with a schema-correct version.
2. Remove all references to nonexistent `documents.supplier_name`.
3. Use live-safe source fields:
   - `documents.provider_id`
   - `documents.extraction_clean` / `documents.extraction_raw`
   - `documents.file_name`, `document_number`, `document_type`, `notes`
   - `document_items.product_id`, `confidence_score`, `description`
   - `price_anomalies` open/resolved status and price fields
   - `sales_imports.status`, `notes`, `source_name`, `source_type`, `file_path`, periods
   - `pos_connections.status`, `sync_status`, `credentials_status`, `connection_mode`, provider metadata
   - `pos_connection_requests.status`, provider metadata
4. Keep the RPC tenant-safe:
   - Validate `p_company_id = ANY(public.user_company_ids())`.
   - Grant only to `authenticated`.
   - Do not use service role in Flutter.
   - Do not weaken RLS.
5. Expand `review_items_type_check` only for real generated operational types:
   - `failed_sales_import`
   - `low_confidence_sales_report`
   - `missing_sales_period`
   - `pos_connection_issue`
   - optionally `price_variation` / `baseline_review` if backed by stable live source rules.
6. Generate review rows from existing real signals; do not create fake rows or hardcode counts.
7. Auto-resolve stale generated items when their source condition is no longer true, except for explicitly ignored/dismissed items.

Flutter fix second:

1. Add the new review types to `ReviewType` and parsing.
2. Update labels/icons/filter groupings for Sales and POS.
3. Update counts so AI review and price counts include all relevant types.
4. Surface sync errors so “All clear” is not shown when the pipeline failed.
5. Preserve existing document/VLM/product/price intelligence flows.
